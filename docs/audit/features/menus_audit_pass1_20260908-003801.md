### 2. What the operator is doing here

The operator plans what the kitchen cooks: they fill the week so that every day carries a breakfast,
a lunch and a dinner before the residents ask for it, and they correct the day that was published
wrong. Done looks like: every day of the planned week carries its dishes, no day of the week is
left empty for the residents to read, and the day that still misses a dish is named on the screen.
The money belongs to the invoice and the payments module; what this module owns is the dish of the
day and the day it belongs to.

The resident half of this module is a pull, not a push: the portal reads GET /menus/today
(mobile/lib/features/tenant/data/tenant_repository.dart:206-216) and the weekly menu
(:218-230). No route of the module sends a notification, so a menu reaches a resident when they
open the app, and a day with no menu shows them nothing.

### 4. The contract

`packages/types/src/contracts/menus.ts` now holds the grid of the domain (the plan state of a day
times the date, because the model carries no status field), one truth entry per action the admin can
take (plan a day, change a day, fill another day with this one, delete a day, read the week and the
day), the layout archetype with the grammar tokens and the module own number, and the next best
action per grid cell and per empty state.

The contract names what the code really has, including the places where a person is still not told:
a plan that changes, a day that is copied and a day that is deleted all reach nobody.

### 5. What was NOT done

- No API route, model or shared type was changed. Every gap that needs one is listed above as still
  open.
- The mobile portal was not touched. The resident half of this module (the menu the resident reads
  on their phone) was not re-audited in this pass.
- The shared components were not changed. The shared week planner
  (apps/web/src/components/ui/WeekMenuPlanner.tsx) is no longer used by the menus page: the grid
  of the week now lives in the page itself, because the planner could not read the week in the
  address bar, could not reach another week and fetched outside the query stack. The component is
  still in the repository and is now unused.
- No screenshot and no browser run: every layout claim is read out of the component geometry and the
  width rule, not measured.
