## 2. Cross-Cutting Dependencies (verified in source)

| Dependency | Location | Contract |
| ---------- | -------- | -------- |
| Floor CRUD | `apps/api/src/routes/floors.ts` | GET list (all, sorted by floorNumber), GET/:id, POST, PUT/:id, DELETE/:id; POST /reseed-services backfills ServiceStatus rows; zod strictObject: floorNumber int >= 0 unique, label <= 50 unique, totalRooms 1-50, amenityCounts (key regex + count 0-10) |
| Floor model | `apps/api/src/models/floor.ts` | floorNumber unique int, label unique, totalRooms 0-50, amenityCounts[]; lean() responses expose `_id` (no transform), client uses `_id` |
| totalRooms sync | `apps/api/src/routes/rooms.ts` recomputeFloorTotalRooms + Room post-save hook | Server-managed only; UI must never PUT totalRooms (API strips it) |
| Delete guards | floors DELETE route | 409 FLOOR_HAS_ROOMS (active rooms), 409 FLOOR_HAS_MACHINES; cascades ServiceStatus rows on delete |
| Rooms by floor | GET `/rooms?floorId=&limit=` | Returns rooms with `beds[]` (bedId, isOccupied, tenantName enriched), monthlyRent, isActive, sharingType |
| Floor services | GET `/services/floor/:floorId/with-complaints` and GET `/services?limit=` | ServiceStatus rows seeded per isPerFloor amenity on create; entries carry status (operational/degraded/down) + openComplaintCount |
| Washing machines | GET `/washing-machines?floorId=` | machineNumber, label, status (available/in_use/other) |
| Amenity definitions | GET `/app-config` amenityDefinitions | key, label, icon (lucide name), isPerFloor, maxPerFloor; drives form amenity steppers and detail chips |
| Complaint intake | `/complaints/new?category=&floorId=` | Service health "report issue" deep link |
