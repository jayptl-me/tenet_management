## Open gaps

The rows below are the findings of the depth pass of 2026-10-21 that the rebuild could not close,
because the gap sits in the API, in the model or in the shared types. The rows the rebuild closed
are recorded in the Closed section below with their date; their ids are the ones of the depth pass
(docs/audit/features/guardians_audit_pass1_20260908-003801.md).

| ID      | Severity | Gap                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          | Path                             |
| ------- | -------- | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------- |
| GU-D3-1 | P2       | GET /guardians cannot filter on the active flag (apps/api/src/routes/guardians.ts:241-286): the filter is the name and the resident only. The office cannot ask the server for the contacts whose portal login is off, so the contact state filter of the roster narrows the page in view instead of the set, and the band says so.                                                                                                                                                                                                          | apps/api/src/routes/guardians.ts |
| GU-D3-2 | P2       | The money of a ward is computed twice, in two functions: the office reads GET /tenants/:id/dues (apps/api/src/routes/tenants.ts:1808-1929) and the guardian reads GET /guardians/me/ward (apps/api/src/routes/guardians.ts:323-366). Both use the one money helper, but they treat an invoice whose total the server cannot compute differently: the guardian total adds the whole total of that invoice, the office total leaves the amount out of the sum and keeps the invoice in the open list. One shared dues function would close it. | apps/api/src/routes/tenants.ts   |
| GU-D3-3 | P2       | A check out flips every guardian of that resident to isActive=false and switches their portal logins off (apps/api/src/routes/tenants.ts:827-843) and sends no notification, so neither the resident nor the person who pays is told that the contact was switched off. The roster names the cell and the contract carries the truth entry; the API change itself is still open.                                                                                                                                                             | apps/api/src/routes/tenants.ts   |
| GU-D3-4 | P3       | The reach of a contact has two doors: DELETE /guardians/:id writes an audit entry with the action delete (apps/api/src/routes/guardians.ts:546-555) and PUT /guardians/:id with isActive false writes the action update (apps/api/src/routes/guardians.ts:511-520). One state change therefore leaves two different trails, and the audit log cannot answer who switched a contact off and when.                                                                                                                                             | apps/api/src/routes/guardians.ts |
| GU-D3-5 | P3       | The guardian search is an unescaped regular expression (apps/api/src/routes/guardians.ts:247-249), so a search with a bracket or a parenthesis makes the query fail. The invoice route escapes its search (apps/api/src/routes/invoices.ts:211); the guardians route does not.                                                                                                                                                                                                                                                               | apps/api/src/routes/guardians.ts |
| GU-D3-6 | P3       | The User model holds no last login field (apps/api/src/models/user.ts), so the office cannot tell whether a guardian ever signed in with the temporary password it handed over. A contact that never signed in looks exactly like one that did, and the create page names the handover as the office's own step.                                                                                                                                                                                                                             | apps/api/src/models/user.ts      |
| GU-D3-7 | P3       | The shared guardian DTOs of packages/types/src/guardian.ts have no importer in the repository, so a page shape can drift from the API contract. The four admin screens declare their own interfaces, as the invoices, the payments and the tenants modules do.                                                                                                                                                                                                                                                                               | packages/types/src/guardian.ts   |

## Closed

| Claim                                                                         | Live proof                                                                                                                                                                                                                                                         |
| ----------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| GU-D2-1 - the module where a relative pays for someone showed no money at all | CLOSED 2026-10-21 - the roster reads the ward's dues summary from the server for every row in view and shows the total still due, the count of the open invoices and the oldest open cycle; a balance the server could not compute is named and never read as zero |
| GU-D2-2 - the contact page had no money either                                | CLOSED 2026-10-21 - the money number of the record is the server's dues summary for the ward, and the invoices behind it are listed with the balance the server computed for each, next to the ledger                                                              |
| GU-D2-3 - the roster could be filtered by nothing but the name                | CLOSED 2026-10-21 - the search, the resident and the contact state live in the address bar, every filter is removable from the band, and the link the resident page sends lands filtered                                                                           |
| GU-D2-4 - the roster said nothing about what its columns meant                | CLOSED 2026-10-21 - a legend under the table names the scope of the search, of the money column, of the reach column and of the contact state filter                                                                                                               |
| GU-D2-5 - the empty state said only "get started"                             | CLOSED 2026-10-21 - the empty state names what the server does when a contact is added and the filtered view says that the server holds nothing for these filters                                                                                                  |
| GU-D2-6 - the create page did not say what the save commits                   | CLOSED 2026-10-21 - the panel names the five things the save does and does not do, including that the resident keeps their own login, their own bills and their own dues view, and it warns when the guardian portal is switched off in the settings               |
| GU-D2-7 - the contact page carried two actions                                | CLOSED 2026-10-21 - the header carries the reach switch, the edit, the other contacts and the resident, and the page lists every other contact of the same resident with its own reach                                                                             |
| GU-D2-8 - the edit page was outside the shared query stack                    | CLOSED 2026-10-21 - the record is read with useApiQuery, the write invalidates the guardian queries and the page hands over to the contact page, which re-reads the record from the server                                                                         |
| GU-D2-9 - the edit page did not say what the save commits                     | CLOSED 2026-10-21 - the panel names the four consequences of the save, including that the same fields are written onto the portal login and that the link to the resident is fixed                                                                                 |
| GU-D2-10 - the switch-off confirmation did not say what is kept               | CLOSED 2026-10-21 - the confirmation names what the server keeps, what it switches off, what it writes in the audit log and who is not told                                                                                                                        |
| GU-D2-11 - nothing said whether the resident still lives here                 | CLOSED 2026-10-21 - the reach column and the ward card both name the stay of the resident, so a contact for a resident who left cannot be read as a contact for a resident in house                                                                                |
| GU-D2-12 - the roster opened with a bare search box and no band               | CLOSED 2026-10-21 - the band carries the count the server reports for the whole filtered set and the three numbers about the page in view, each with its scope                                                                                                     |
