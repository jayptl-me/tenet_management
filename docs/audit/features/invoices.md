because the gap sits in the API or in the shared types. The rows the rebuild closed are recorded in
the Closed section below with their date; their ids are the ones of the depth pass
(docs/audit/features/invoices_audit_pass1_20260908-003801.md).

| ID       | Severity | Gap                                                                                                                                                                                                                                                                                                                                                                                                                                             | Paths                                                                                 |

A trail of one invoice can therefore only be assembled from the newest entries of the resource, and the invoice page says so instead of pretending the trail is complete.                                                                                                                                | apps/api/src/routes/audit.ts; apps/web/src/app/(admin)/invoices/[id]/page.tsx         |

The admin screen now says so before the delete, but the resident is still not reached.                                                                                                                                                                                                            | apps/api/src/routes/invoices.ts; apps/web/src/app/(admin)/invoices/page.tsx           |
| INV-D2-3 | P2       | PUT /invoices/:id with status=sent moves a draft or reopens a cancelled bill without notifying the resident (apps/api/src/routes/invoices.ts:774-936). Only a moved amount and a cancellation push a payment_reminder. The edit screen says so before the save, but the resident is still not reached.                                                                                                                                          | apps/api/src/routes/invoices.ts; apps/web/src/app/(admin)/invoices/[id]/edit/page.tsx |

| INV-D2-5 | P3       | The aging report and the status filter answer different questions: the bars count every open invoice by the days past its due date, while the tab reads the status the daily sweep wrote (apps/api/src/routes/invoices.ts:435-503, :189-203). ## Closed

| Claim                                                                                                                     | Live proof                                                                                                                                                                                                                                                                            |
| ------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| INV-D1-1 - the ledger ignored its own address bar, so a filtered view could not be shared or cited                        | CLOSED 2026-10-21 - the status, the month, the resident and the search live in the address bar, so /invoices?status=overdue&month=2026-10 is a link that lands on the rows it names                                                                                                   |
| INV-D1-2 - the tab counts answered a different question than the rows under the filters                                   | CLOSED 2026-10-21 - every count of the band is read from GET /invoices for the same filtered set the table shows, so a tab count is exactly the number of rows the operator gets after clicking it                                                                                    |
| INV-D1-3 - the CSV export silently truncated at 100 rows and dropped the search and the resident filter                   | CLOSED 2026-10-21 - the export sends every active filter including the search, walks the pages of the filtered set (the API clamps a page to 100) and reports how many invoices the server holds against the rows the file carries                                                    |
| INV-D1-4 - the ledger rows were not navigable: the invoice number and the resident were plain text                        | CLOSED 2026-10-21 - the invoice number links to /invoices/[id], the resident to /tenants/[id] and the room to /rooms/[id], in the table and in the mobile card                                                                                                                        |
| INV-D1-5 - the empty state always said "No invoices yet", even for a filter that held nothing                             | CLOSED 2026-10-21 - the empty state answers the question that was asked: a status, a filter or the whole ledger each get their own wording and their own next action                                                                                                                  |
| INV-D1-6 - the detail page had no state progression, only a badge and a progress bar                                      | CLOSED 2026-10-21 - the detail page renders the shared invoice stepper, whose states and transitions come from the same vocabulary the portal is generated from, and it names who moves the record and when                                                                           |
| INV-D1-7 - the office could only cancel a bill from the edit page, where the balance is not on screen                     | CLOSED 2026-10-21 - the detail page carries Cancel invoice in the header and in the rail, it writes through the same route, it re-reads the invoice and it shows the refusal of the server when the bill still carries a balance                                                      |
| INV-D1-8 - the payment history had no visible link to the payment record and named neither the date nor the UTR           | CLOSED 2026-10-21 - every row of the payment history links to /payments/[id] and the table carries the date, the amount, the method and the status                                                                                                                                    |
| INV-D1-9 - the detail page never showed the resident's own view of what they owe next                                     | CLOSED 2026-10-21 - a rail card reads GET /tenants/:id/dues and shows the total the resident owes, the open invoices and the balance of each, every number being the server's                                                                                                         |
| INV-D1-10 - the contract promised a trail of the invoice that no screen showed                                            | CLOSED 2026-10-21 - the detail page renders the activity trail of the invoice and states that the audit route cannot filter by record, so the trail is the one inside the newest invoice entries                                                                                      |
| INV-D1-11 - the compose form warned about a duplicate instead of refusing it, and the server refused the write            | CLOSED 2026-10-21 - a duplicate for the resident and the month is a wall: the write is blocked, the existing invoice is named and linked, and the reason (one invoice per resident and month) is given                                                                                |
| INV-D1-12 - the compose form offered a discount preset that the server refuses, because a line amount may not be negative | CLOSED 2026-10-21 - the preset is gone and the form says how a discount is applied: by lowering the charge it belongs to, not by a negative line                                                                                                                                      |
| INV-D1-13 - the compose form did not say what the server would do with the bill the office is about to issue              | CLOSED 2026-10-21 - the rail names the consequence before the write: the charge, the due date, the status the server writes, the pending obligation it opens, the notification the resident gets and the split of the lines into rent, electricity and other charges by their wording |
| INV-D1-14 - the edit page did not say that an edit moves what the resident owes, nor that the resident is told            | CLOSED 2026-10-21 - the rail states what the save does: a moved amount notifies the resident with the old and the new number, a cancellation notifies them too, and sending a draft does not                                                                                          |
| GET /invoices/:id/payment-status was a live endpoint with no consumer                                                     | REMOVED 2026-10-21 - endpoint deleted, zero consumers                                                                                                                                                                                                                                 |
