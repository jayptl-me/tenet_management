## Open gaps

The rows below are the findings of the depth pass of 2026-10-21 that the rebuild could not close,
because the gap sits in the API or in the shared types. The rows the rebuild closed are recorded in
the Closed section below with their date; their ids are the ones of the depth pass
(docs/audit/features/electricity_audit_pass1_20260908-003801.md).

| ID       | Severity | Gap                                                                                                                                                                                                                                                                                                                                                                                                                                                                               | Paths                                                                                  |
| -------- | -------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------------- |
| ELE-D2-1 | P2       | POST /electricity/:id/distribute skips two kinds of invoice without counting an error and without charging them: a cancelled invoice, and an invoice that is already paid and already carries electricity (apps/api/src/routes/electricity.ts:774-787). The bill still reads distributed, so the month looks collected while those residents were never charged and were never told. The bill detail names the invoices that carry no share, but the server still charges nobody. | apps/api/src/routes/electricity.ts; apps/web/src/app/(admin)/electricity/[id]/page.tsx |
| ELE-D2-2 | P2       | POST /electricity/:id/finalize checks nothing about the variance: the server finalizes a bill whose readings do not add up to the utility total (apps/api/src/routes/electricity.ts:644-689). The office screen refuses it and says that the server does not check it, but a direct call finalizes it.                                                                                                                                                                            | apps/api/src/routes/electricity.ts; apps/web/src/app/(admin)/electricity/[id]/page.tsx |
| ELE-D2-3 | P3       | GET /electricity/:id links a bill to the invoices of the residents of its rooms, but it selects every tenant of those rooms and not the residents who were in the room during the billing month (apps/api/src/routes/electricity.ts:450-467). An invoice of somebody who was not in that room that month therefore appears in the list with no share, and the page has to say so.                                                                                                 | apps/api/src/routes/electricity.ts; apps/web/src/app/(admin)/electricity/[id]/page.tsx |
| ELE-D2-4 | P3       | The shared lifecycle vocabulary carries no electricity domain (packages/types/src/lifecycle.json), so the module cannot use the shared StatusStepper. Adding the domain also regenerates the portal file (mobile/lib/core/models/lifecycle.dart), which is outside this module, so the module draws its own progression from the model enum and the two routes.                                                                                                                   | packages/types/src/lifecycle.json; apps/web/src/app/(admin)/electricity/[id]/page.tsx  |
| ELE-D2-5 | P3       | The shared electricity DTOs of packages/types/src/electricity.ts have no importer and do not describe the API response: the lean rows of GET /electricity carry _id and not id, and the detail adds the linked invoices. The four admin screens keep their own interfaces, so a page shape can drift from the API contract.                                                                                                                                                       | packages/types/src/electricity.ts; apps/web/src/app/(admin)/electricity                |
