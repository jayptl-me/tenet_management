### 2. What the operator is doing here

The operator reads the whole building at once and decides what to work on in the next hour. The
dashboard owns no record and writes nothing: it is a read model over the modules. Done looks like:
the number at the top is the one that decides the day, every act now link opens the list it names
with that list already filtered, and every number on the screen is the count the server holds for the
set it names.

### 4. The contract

`packages/types/src/contracts/dashboard.ts` now holds the grid of the domain (the dashboard has no
model and no status, so it declares none), one truth entry per action the operator can take on the
screen (read the band and follow a link, read the money, read the bills of the month, read the
building, read the complaint queue, read the service health, read the meal feedback, read the
leads), the layout archetype with the grammar tokens and the module own number, and the next best
action per queue and per empty state.

The contract names the three places where the code still cannot do what the screen would like:
the ledger cannot be filtered by billing month from a link, the service board cannot be filtered by
state from a link, and the aging rails count the open and in-progress tickets while the window they
open holds every complaint raised in it.

### 5. What was NOT done

- No API route, model or shared type was changed. Every gap that needs one is listed above as
  still open.
- No other module was changed. The payments screen, the services screen and the enquiries screen
  keep the gaps the dashboard names (DASH-D3-1, DASH-D3-2, DASH-D3-10).
- No shared component was changed. The screen no longer renders the shared triage banner
  (apps/web/src/components/admin/AttentionRequiredBanner.tsx) or the shared meal ledger
  (apps/web/src/components/ui/MealFeedbackLedger.tsx): the banner counted the aging complaints on
  the screen, and the meal ledger writes numbers the server never sent. Both files are still in the
  repository and are now unused by this screen.
- The mobile portal was not touched. The resident half of the money the dashboard shows (the bill a
  resident has not paid) was not re-audited in this pass.
- No screenshot and no browser run: every layout claim is read out of the component geometry and the
  width rule, not measured.
