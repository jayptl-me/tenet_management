## Open gaps

The rows below are the findings of the depth pass of 2026-10-21 that the rebuild could not close,
because the gap sits in the API, in the model or in the shared types. The rows the rebuild closed are
recorded in the Closed section below with their date; their ids are the ones of the depth pass
(docs/audit/features/laundry_audit_pass1_20260908-003801.md).

| ID            | Severity | Gap                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       | Path                               |
| ------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------- |
| LAUNDRY-D3-1  | P2       | The office cannot close a slot after its day. PUT /laundry-slots/:id compares the date the write carries with the server's today and refuses the whole write when the day has passed (apps/api/src/routes/laundry.ts:376-381), so a confirmed slot of yesterday stays confirmed, cannot be corrected and still holds its place at that time. A guard that only refuses a move into the past would close it. The screen: apps/web/src/app/(admin)/laundry/[id]/page.tsx.                                                   | apps/api/src/routes/laundry.ts     |
| LAUNDRY-D3-2  | P2       | A completed slot still holds a place. The capacity count of a slot time excludes only the cancelled bookings (apps/api/src/routes/laundry.ts:276-280), so a slot whose laundry is already finished refuses a new booking at that same time, and the office sees a full time with a place nobody uses. Counting only the bookings that are still to come would close it. The screen: apps/web/src/app/(admin)/laundry/page.tsx.                                                                                            | apps/api/src/routes/laundry.ts     |
| LAUNDRY-D3-3  | P2       | The server accepts a slot for a resident who has left. POST /laundry-slots checks no state of the resident (apps/api/src/routes/laundry.ts:257-292), so a booking can hold a place of the five for nobody while the resident is gone. A check of the resident, or a refusal of an inactive one, would close it. The screen: apps/web/src/app/(admin)/laundry/new/page.tsx.                                                                                                                                                | apps/api/src/routes/laundry.ts     |
| LAUNDRY-D3-4  | P2       | A booking the office makes for a resident is silent. The server sends one message only when a slot is confirmed (apps/api/src/routes/laundry.ts:434-443), so a slot the office books on behalf of a resident reaches them only when somebody confirms it, and the resident may never come down. A message on the booking would close it. The screen: apps/web/src/app/(admin)/laundry/new/page.tsx.                                                                                                                       | apps/api/src/routes/laundry.ts     |
| LAUNDRY-D3-5  | P3       | The laundry domain has no entry in the shared lifecycle vocabulary (packages/types/src/lifecycle.json), so the shared stepper cannot render the ladder of a slot and the portal cannot show the progression either. The admin detail page draws the ladder of the module itself until the domain is added. A domain and a status union in the vocabulary, and the generated Dart, would close it. The screen: apps/web/src/app/(admin)/laundry/[id]/page.tsx.                                                             | packages/types/src/lifecycle.json  |
| LAUNDRY-D3-6  | P3       | The shared status map gives a completed slot and a cancelled slot the same neutral tone (packages/types/src/tokens.ts:97-101), while the portal paints a cancellation as a refusal and a finished slot as work brought to an end (mobile/lib/features/shared/widgets/portal_widgets.dart:210-239). The two states look the same in the admin list. A tone of its own for each would close it. The screen: apps/web/src/app/(admin)/laundry/page.tsx.                                                                      | packages/types/src/tokens.ts       |
| LAUNDRY-D3-7  | P3       | The shared error parser has no entry for the codes the laundry route refuses with (INVALID_SLOT_DATE, INVALID_DATE, INVALID_TENANT, INVALID_STATUS), and it maps every 400 to one generic sentence (apps/web/src/lib/errorParser.ts:41-81). The four screens of this module read the message of the server themselves, so the office reads the reason here, but every other caller of the route still gets the generic sentence. An entry per code would close it. The screen: apps/web/src/app/(admin)/laundry/page.tsx. | apps/web/src/lib/errorParser.ts    |
| LAUNDRY-D3-8  | P3       | A slot names no machine. The model holds no machine reference (apps/api/src/models/laundrySlot.ts:15-47), so the office cannot tell a resident which washer to use and two residents can hold a place in the same queue. Pass 1 declared the linkage out of scope; it stays out of scope until the model carries it. The screen: apps/web/src/app/(admin)/laundry/[id]/page.tsx.                                                                                                                                          | apps/api/src/models/laundrySlot.ts |
| LAUNDRY-D3-9  | P3       | The server cannot filter on a slot time, only on a day (apps/api/src/routes/laundry.ts:176-198), so the queue of a time has to be picked out of the day by the screen. A filter on the time would let the server answer the question the module asks. The screen: apps/web/src/app/(admin)/laundry/[id]/page.tsx.                                                                                                                                                                                                         | apps/api/src/routes/laundry.ts     |
| LAUNDRY-D3-10 | P3       | The load of a slot time is not a number the server holds: the API has no aggregate of the places of a time, so the band and the column of the list are computed by the screen from the rows it read. An aggregate on the list route would close it. The screen: apps/web/src/app/(admin)/laundry/page.tsx.                                                                                                                                                                                                                | apps/api/src/routes/laundry.ts     |
| LAUNDRY-D3-11 | P3       | The shared laundry DTOs of packages/types/src/laundry.ts have no importer in the repository: the API uses its own model interface and the four admin screens declare their own interfaces, so a page shape can drift from the API contract. The screens: apps/web/src/app/(admin)/laundry.                                                                                                                                                                                                                                | packages/types/src/laundry.ts      |
| LAUNDRY-D3-12 | P3       | The write trail of a slot is not permanent evidence: the audit entries expire after 90 days (apps/api/src/models/auditLog.ts:81-82), so a change that reached nobody leaves no trace after a quarter. The screen: apps/web/src/app/(admin)/laundry/[id]/page.tsx.                                                                                                                                                                                                                                                         | apps/api/src/models/auditLog.ts    |
