### 2. What the operator is doing here

The operator keeps the register of what the PG owns usable: what is broken, what is due for
service, what is running out, and where every item lives. Nothing here is a person and nothing
here moves money; the two clocks the module carries are the low stock threshold and the next
service date. Done looks like: every item carries a state that says whether it can be used,
every item links to the room or the floor it lives in, nothing sits at or below its threshold
without a decision, no service date passes unnoticed, and every write is on the record of the
item.

### 4. The contract

`packages/types/src/contracts/assets.ts` now holds the grid of the domain (the five states the
model really has: available, in use, under maintenance, damaged, retired), one truth entry per
action the admin can take (register, change the state, put it somewhere, record a service,
adjust the count, retire, read the register), the layout archetype with the grammar tokens and
the module own number, and the next best action per state and per empty state.

The contract names what the code really has, including the places where a person is still not
told: an asset registered already out of service, an asset that comes back into service, a
retirement, a move to another room, a new count and a new service date all reach nobody.

### 5. What was NOT done

- No API route, model or shared type was changed. Every gap that needs one is listed above as
  still open.
- The mobile portal was not touched. The resident half of this module (the notification the
  residents of a room receive) was not re-audited in this pass.
- The shared components were not changed. Two of them were dropped from this module: the low
  stock and the service due banners, because they fetched the same endpoints a second time
  outside the shared query stack; they are still in the repository and are now unused by this
  module.
- The room and the floor pages were not touched, so a room still does not list its assets; the
  assets of a place are visible from the asset that lives there.
- No screenshot and no browser run: every layout claim is read out of the component geometry and
  the width rule, not measured.
- One shared defect was found outside this module and is reported to the main thread rather than
  fixed here: a controlled DatePicker hands its change event to a handler typed as a string
  (apps/web/src/components/ui/DatePicker.tsx:203-221), so the month filter of the electricity
  module writes an object into the address bar instead of the month.
