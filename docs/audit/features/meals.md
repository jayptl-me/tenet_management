### 2. What the operator is doing here

The operator reads what the residents said about the food and closes the loop on the ratings that
were bad. The money belongs to the invoice module and the payments module; what this module owns is
the rating, the words that came with it and the answer the office gave. Done looks like: every
rating that was read has been read, the low ones have been actioned, and the resident who left each
rating was told what the office did with it.

### 4. The contract

`packages/types/src/contracts/meals.ts` now holds the ladder of the domain (the resident rated the
meal, the office read it, the kitchen acted on it), one truth entry per action the office can take
(acknowledge, action, edit, record a rating on a resident behalf, delete, read the ledger, and the
resident rating a meal), the layout archetype with the grammar tokens and the module own number,
and the next best action per state and per empty state.

The contract names what the code really has, including the places where a person is still not told:
a rating the office records on a resident behalf reaches nobody, the resident path writes no audit
entry, and a delete removes the words of a resident without a word to anyone.

The contract declares no dwell, and that is deliberate: the model carries no clock on the triage
(apps/api/src/models/mealFeedback.ts:55), so the age of a rating cannot be read from the record.

### 5. What was NOT done

- No API route, model or shared type was changed. Every gap that needs one is listed above as still
  open.
- The mobile portal was not touched. The resident half of this module (the rating the resident
  leaves and the message they read) was not re-audited in this pass.
- The shared components were not changed. The summary strip
  (apps/web/src/components/ui/FeedbackSummaryStrip.tsx) is no longer rendered by the meals list,
  because it computes an average on the client; the strip itself is still in the repository and is
  now unused.
- No screenshot and no browser run: every layout claim is read out of the component geometry and the
  width rule, not measured.
- The meals list is not in the width rule table of the layout gate
  (scripts/audit/check-layout-frame.mjs:73-139), so the first data row of the list was not measured
  at a fixed viewport. The list page was built to the same band as the rooms list.
